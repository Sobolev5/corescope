# CoreScope

Отдельный Windows-монитор на Rust с локальной панелью, вдохновлённый архитектурой NetScope: сборщик → снимок системы → axum → встроенный интерфейс. NetScope и Npcap для работы не нужны.

## Запуск

Скачайте `CoreScope-Setup-0.4.1.exe` из [Releases](https://github.com/Sobolev5/corescope/releases). Установщик RU/EN создаёт ярлыки и запись удаления приложения; автозапуск в трей включается по желанию. Если WebView2 отсутствует, установщик скачивает его с сайта Microsoft; для этого нужен интернет. Установщик пока не подписан цифровым сертификатом.

Для portable-запуска распакуйте весь архив и откройте `corescope.exe`. Для разработки: `cargo run --release`. Открывается отдельное окно Windows с WebView2. Закрытие окна по умолчанию скрывает его в трей; сбор данных продолжается. Нажатие значка CPU или повторный запуск возвращает окно. Правый клик по значку открывает меню; «Выход» завершает программу. Требуется Windows x64, .NET Framework 4.7.2+ для расширенных датчиков и Microsoft Edge WebView2 Runtime. `WebView2Loader.dll` и папка `hardware` должны оставаться рядом с exe.

RU/EN переключается в шапке и меню трея. Язык и поведение закрытия сохраняются в `%LOCALAPPDATA%\CoreScope\settings.json`. В «Настройках» можно отключить закрытие в трей. Системные ошибки Windows и названия аппаратных датчиков сохраняют исходный язык.

Обычный запуск использует свободный локальный порт. Для разработки и проверки API: `--no-open --port 8899` запускает только сервер. Режим сервера работает до завершения процесса; остановить portable-экземпляры можно через `dist\Stop-CoreScope.ps1`.

## Управление ядром

Нажмите ядро на изометрической карте или карточку CPU. Справа появятся процессы с доступом к этому CPU. «Запретить» немедленно убирает выбранный CPU из affinity процесса; другие CPU сохраняются. Во вкладке «Запрещено» кнопка «Разрешить» возвращает доступ. Последнее разрешённое ядро запретить нельзя. Поиск в этом списке независим от общей таблицы. Нажатие имени процесса открывает его подробности и память ниже.

Список описывает разрешение планировщику, а не точный момент исполнения потока. Системные процессы могут отказать в изменении привязки: ошибка Windows появится в уведомлении.

## Возможности

- Изометрическая схема CPU/RAM и загрузка каждого логического процессора раз в секунду.
- Все доступные процессы, поиск по имени/PID, сортировка по CPU и памяти, фильтр по разрешённому CPU.
- Чтение и изменение process affinity через Windows API. Выберите процесс, переключите CPU и нажмите «Применить». «Все CPU» подготавливает сброс; нажмите «Применить» для сохранения.
- Запуск .exe с привязкой: CreateProcessW(CREATE_SUSPENDED), SetProcessAffinityMask, ResumeThread. Пока без аргументов командной строки.
- Виртуальные committed-области через VirtualQueryEx: адрес, размер, image/private/mapped, protection. Рабочий набор показывается отдельно: объём committed-памяти не равен объёму резидентной RAM.
- Независимые сборщики Windows ACPI/Storage и встроенной LibreHardwareMonitorLib: температура, обороты, мощность, напряжение, частота, загрузка. Опрос каждые 5 секунд плюс время чтения; у показаний указан источник и время замера.
- Графики температур: последние 120 успешных замеров каждого датчика, минимум и максимум этого интервала. История хранится в памяти до выхода из CoreScope; паузы в работе провайдера не заполняются вымышленными значениями.

## Датчики

Отдельное приложение LibreHardwareMonitor не требуется. Термозоны ACPI и температура накопителей читаются через Windows; расширенные датчики — через включённую библиотеку LibreHardwareMonitorLib 0.9.6 в фоновом процессе без окна. В настройках можно отключить расширенный сбор, сохранив источники Windows.

ACPI — термозона прошивки, а не температура конкретного ядра. Доступность датчиков зависит от оборудования, прав и драйверов. Часть измерений CPU требует PawnIO; CoreScope его автоматически не устанавливает. Если источник CPU возвращает недоступное нулевое измерение, оно исключается, а интерфейс показывает отсутствие температуры CPU. Диагностика доступна в панели датчиков. Не все машины публикуют температуру каждого ядра.

Неизменённые библиотеки и лицензии находятся в `assets/hardware`; версия, SHA-256 официального архива и ссылка на соответствующий исходный код указаны в `SOURCE.txt`. Основной проект — MIT, LibreHardwareMonitorLib — MPL-2.0, остальные компоненты имеют собственные лицензии.

## Что именно означают данные

**Affinity — разрешение планировщику, не наблюдение выполнения.** Многопоточный процесс может одновременно исполняться на нескольких CPU и мигрировать между ними. Эта версия не записывает ETW context-switch events и не показывает, на каком ядре конкретный поток выполнялся в каждый момент. Для этого нужен отдельный ETW-сборщик с повышенными правами. Фильтр по CPU означает «процессу разрешено это ядро».

CPU N — логический процессор Windows, не обязательно отдельное физическое ядро. Карта схематическая: она не изображает разводку платы или физическое размещение памяти. Четыре полосы RAM — индикатор использования, а не четыре обнаруженные планки.

Оперативная память не состоит из «регистров процесса». VirtualQueryEx показывает виртуальные адреса, а не физические адреса RAM, номера DIMM или содержимое памяти. Регистры CPU относятся к контексту потока и здесь не читаются.

Максимальная температура в верхней карточке — максимум среди **всех** доступных температурных датчиков, а не CPU Package. Датчики показаны с исходным именем и аппаратным родителем. Температура package не подставляется вместо температуры отдельного ядра.

## Ограничения и безопасность

- На системах с несколькими processor groups изменение affinity отключено: простая маска не описывает все CPU таких систем.
- Защищённые/системные процессы могут отказать в доступе. Ошибка Windows отображается пользователю. Автоматического повышения прав нет.
- Для защиты от переиспользования PID перед операциями проверяется время создания процесса на том же открытом handle.
- Сервер слушает только 127.0.0.1; проверяет Host/Origin, изменения требуют случайного токена текущего запуска. Не публикуйте через reverse proxy. Это не изоляция от других программ того же пользователя.
- Привязка не сохраняется между перезапусками процесса. Приложение может изменить собственную affinity; лаунчеры могут передать запуск уже существующему процессу.
- Процессный CPU нормирован на суммарную мощность всех логических CPU (0–100%). Первый снимок появляется после интервала измерения.

## Разработка

`cargo test` · `cargo build --release` · `cargo fmt --check`

`powershell -NoProfile -File scripts/build-installer.ps1` — установщик (нужен Inno Setup 6.1+).

`scripts/smoke.ps1` проверяет API и affinity; `scripts/sensors-smoke.ps1` — реальные датчики, историю и независимость источников на машине с поддерживаемыми ACPI/Storage и GPU.

`src/platform.rs` — handles, affinity, запуск, VirtualQueryEx.
`src/main.rs` — сборщики, локальный API, защита запросов.
`src/desktop.rs` — окно Windows, DPI, цикл сообщений, жизненный цикл.
`src/webview.rs` — WebView2 host из NetScope (MIT); загрузчик Microsoft включён со своей лицензией.
`assets/index.html` — автономный UI, без CDN и сетевых шрифтов.
`assets/sensors.ps1` — чтение WMI датчиков (встроено в exe).

API: GET `/api/snapshot`, GET `/api/process/{pid}/memory?identity=...`, POST `/api/process/{pid}/affinity` (`identity`, `cores`), POST `/api/launch` (`path`, `cores`). POST требует `X-CoreScope-Token` из текущей страницы.

POST `/api/process/{pid}/core` (`identity`, `core`, `enabled`) меняет один бит текущей маски на открытом handle. Пустая итоговая маска и устаревшая identity отклоняются. Внешний процесс всё ещё может параллельно изменить собственную affinity; системного compare-and-swap для неё нет.
